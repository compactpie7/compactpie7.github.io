# Публикация

## Механизм

Сайт публикуется через GitHub Pages как пользовательский сайт репозитория `compactpie7/compactpie7.github.io`. По правилам проекта публикуется ветка `main`, директория `/` (root). Файлов деплоя (`.github/workflows`, `CNAME`) в проекте нет. Настройку Settings → Pages нужно проверить на GitHub, из репозитория она не видна.

## Процесс обновления

1. Разработка ведётся в ветке `ai/site-redesign`.
2. После локальной проверки (чек-лист в `DEVELOPMENT.md`) изменения вливаются в `main`. Коммиты, push и слияние выполняются только с отдельного разрешения владельца.
3. GitHub Pages собирает и публикует сайт автоматически, обычно за 1–2 минуты.
4. После публикации проверить сайт на https://compactpie7.github.io/, особенно пути к файлам с пробелами и воспроизведение звука.

## Особенности

- Хостинг статический: нет серверного кода и настраиваемых HTTP-заголовков.
- Файловая система на хостинге регистрозависима, на Windows ошибка регистра в пути не заметна.
- Откат: вернуть `main` к предыдущему коммиту или создать revert-коммит.
- Content-Security-Policy пока не добавлена: сначала нужно проверить все ресурсы.
