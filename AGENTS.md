# AGENTS.md — постоянные правила разработки проекта

Этот файл описывает обязательные правила для ИИ-агентов и разработчиков, работающих с проектом. Правила действуют постоянно, пока пользователь явно не изменит их.

## 1. Контекст проекта

- Проект: персональный сайт-портфолио музыканта и композитора.
- Хостинг: GitHub Pages (репозиторий `compactpie7/compactpie7.github.io`, пользовательский сайт).
- Публикуемая ветка: `main`, директория `/` (root).
- Рабочая ветка разработки: `ai/site-redesign`.
- Основные технологии: HTML5, CSS3 и при необходимости Vanilla JavaScript.

### Текущая структура (на момент создания файла)

| Путь | Назначение |
|---|---|
| `index.html` | Единственная страница и точка входа. Подключает `style.css` и шрифты Google Fonts (Comfortaa, Fredoka). |
| `style.css` | Все стили сайта. Цвета заданы через CSS-переменные в `:root`. |
| `README.md` | Краткое описание репозитория (сейчас содержит только заголовок и тестовую строку). |
| `files/` | Медиафайлы: два аудиофайла `.mp3` и фоновое изображение `.png`. |

JavaScript, папка `docs/` и конфигурация деплоя (`.github/`, `CNAME`) в проекте на данный момент отсутствуют.

## 2. Архитектурные правила

- Предпочитай простые, понятные решения.
- Не добавляй React, Vue, Angular, сборщики и сторонние библиотеки без обоснованной необходимости и согласования с пользователем.
- Разделяй структуру (HTML), оформление (CSS) и поведение (JavaScript). Не размещай стили и скрипты внутри HTML без веской причины.
- Не дублируй код без необходимости: повторяющиеся значения выноси в CSS-переменные, повторяющиеся блоки оформляй общими классами.
- Используй относительные пути к локальным ресурсам (например, `files/track.mp3`, а не `/files/track.mp3`).
- Не проводи масштабную реорганизацию файлов без предварительного плана, согласованного с пользователем.
- Следуй существующему стилю кода: отступ в 4 пробела, CSS-переменные для цветов, имена классов в нижнем регистре через дефис.

## 3. Ограничения по контенту

- Не придумывай имя артиста, биографию, контакты, ссылки на социальные сети, отзывы, награды, музыкальные достижения или услуги.
- Используй только достоверные данные из проекта или предоставленные пользователем. Если данных не хватает, оставляй явный запрос пользователю, а не вымышленный текст.
- Не заменяй существующие музыкальные произведения вымышленными.
- Не изменяй, не перекодируй поверх оригинала и не удаляй оригинальные аудиофайлы без разрешения пользователя.

## 4. Дизайн и доступность

- Mobile-first и адаптивная вёрстка.
- Семантический HTML (`header`, `main`, `section`, `footer`, корректная иерархия заголовков).
- Достаточный контраст текста (ориентир — WCAG AA).
- Полная поддержка клавиатурной навигации.
- Видимые состояния `:focus` / `:focus-visible` у всех интерактивных элементов.
- Поддержка `prefers-reduced-motion`: анимации и переходы отключаются или упрощаются.
- Корректные альтернативные тексты изображений; декоративные изображения получают пустой `alt=""`.
- Не использовать autoplay для музыки.

## 5. Музыкальный плеер

- Использовать совместимые с браузерами HTML5 Audio API и `HTMLAudioElement`.
- Не загружать аудиофайлы заранее без необходимости (`preload="none"` или `preload="metadata"`).
- Обеспечить понятные состояния воспроизведения: воспроизведение, пауза, загрузка, ошибка.
- Предусмотреть обработку ошибок загрузки аудио (событие `error`, понятное сообщение пользователю).
- Не допускать одновременного воспроизведения нескольких треков: при запуске одного трека остальные ставятся на паузу.
- Все элементы управления должны быть доступны с клавиатуры и иметь понятные подписи (`aria-label` или видимый текст).

## 6. Безопасность

- Никогда не помещать API-ключи, пароли и токены в исходный код сайта.
- Не использовать небезопасную вставку содержимого через `innerHTML`; для текста применяй `textContent` или создание элементов через DOM API.
- Внешние ссылки с `target="_blank"` должны использовать `rel="noopener noreferrer"`.
- Не подключать неизвестные внешние библиотеки и скрипты без согласования.
- Учитывать, что GitHub Pages — статический хостинг без собственного серверного кода: нет серверной валидации, сессий и настраиваемых HTTP-заголовков.
- Не обещать защиту от DDoS или иных атак, которую архитектура сайта обеспечить не может.

## 7. Производительность и SEO

- Оптимизировать изображения без потери оригинальных файлов: сжатые версии сохраняются отдельно, оригиналы не перезаписываются.
- Использовать подходящие `preload`, `loading="lazy"` и современные форматы ресурсов (WebP, AVIF, SVG), где это уместно.
- Добавлять корректные `title`, `meta description`, Open Graph и favicon, когда доступны необходимые данные.
- Не допускать неоправданной загрузки аудио и сторонних ресурсов; по возможности добавлять `preconnect` для внешних доменов или размещать ресурсы локально.
- Следить за размером файлов в `files/`, особенно аудио и фонового изображения.

## 8. Рабочий процесс

- Перед масштабными изменениями сначала анализировать существующий код и предлагать план.
- Перед изменением нескольких файлов объяснять назначение изменений.
- Сохранять совместимость с GitHub Pages (статические файлы, отсутствие серверной логики, регистрозависимые пути).
- Не менять ветку Git самостоятельно.
- Не выполнять `git push`, `git commit`, публикацию сайта и удаление файлов без отдельного разрешения пользователя.
- Не устанавливать зависимости без согласования.
- Не включать автоматическое подтверждение инструментов.
- По завершении каждой задачи сообщать: изменённые файлы, выполненные проверки, обнаруженные проблемы и оставшиеся задачи.
